# OpenDevice Node 废旧手机模块控制台设计

> 状态：方向已批准，等待书面规格复核
>
> 日期：2026-08-25
>
> 所属产品：OpenDevice Forge
>
> 首个交付：Android 手机端微内核 + AI 模型节点模块

## 1. 决策摘要

OpenDevice Forge 不再把“手机运行大模型”视为单一用途，而是把废旧 Android 手机改造成可重复配置的模块节点。手机端产品名暂用 `OpenDevice Node`：它既能脱离电脑独立管理，也能被桌面端 OpenDevice Forge 发现和管理。

大模型是第一个真实模块，不是内核特例。后续模块可将手机改造成信息显示屏、视频节点、网络工具、路由节点、蓝牙或 USB 玩具控制器，以及其他社区工作流。模块可来自官方目录、经过审核的社区目录、固定版本的 GitHub Release/commit 或本地包。

模块对使用者呈现为可发现、可安装、可更新和可卸载的 App 式产品：具有名称、图标、截图、版本、发布者、许可证、权限、兼容性、更新记录和独立工作台。系统能够根据用户描述和当前手机的真实能力主动搜索、筛选和推荐插件，但任何安装都必须在手机上展示来源、权限和风险并由用户确认。

插件创作同时服务普通用户和开发者。普通用户使用可视化制作器组合页面、数据源、定时任务和受控设备动作；开发者使用 SDK、模板、模拟设备和沙箱调试器。两条路线输出同一种可签名 `.odmodule` 包，先本地测试，再按用户单独授权发布到 GitHub Release 或公共目录。

首个交付只实现足以承载真实 AI 模块的手机端微内核和 AI 模块闭环。GitHub 市场、脚本沙箱、显示屏、视频、玩具、路由、公网网关和 Root Broker 保留稳定契约，分别在后续里程碑实现，不能以概念页面冒充可用能力。

## 2. 用户目标与完成形态

目标用户拥有一台闲置的 HUAWEI CDL-AN50（HUAWEI nova 7 SE 5G 活力版系列）和一台电脑，希望：

1. 手机不依赖电脑即可选择、下载和运行开源模型；
2. 电脑可以使用标准 OpenAI 客户端调用手机上的模型；
3. 以后获得 VPS 后，外地电脑可以通过 `https://公网 IP:端口/v1` 调用手机节点；
4. 同一控制台以后可以安装显示屏、视频、玩具、网络和其他模块；
5. 社区模块可以通过 GitHub URL 获取，但必须具备来源固定、完整性校验、权限说明、隔离、停用和回退能力；
6. 用户可以像在应用商店中一样搜索、比较、安装、更新和卸载插件；
7. 普通用户和开发者都可以制作、测试和打包自己的插件；
8. Root 是可选的高危能力层，不是手机节点、模型服务或模块市场的前置条件。

手机目前未通过 ADB 连接到开发电脑。型号系列来自既有项目证据，实际 Android 版本、ABI、总内存、可用内存、存储、电池和热状态仍必须在首轮真机连接时读取；在取得实测数据前，不承诺具体模型速度或可支持的最大模型。

## 3. 交付分解

产品按以下顺序交付，每一项拥有独立规格、实现计划和验收证据：

1. **OpenDevice Node 微内核 + AI 模型节点模块**：本规格的实现范围；
2. **OpenDevice Forge 桌面管理插件**：发现、配对、部署和管理手机节点；
3. **插件发现中心与 GitHub 安装**：多来源搜索、兼容筛选、安装确认、更新和回退；
4. **隔离脚本运行器**：JavaScript/WASM 沙箱、能力授权、配额和审计；
5. **插件创作中心与开发者 SDK**：可视化制作、模板、模拟、调试、打包和签名；
6. **公网 IP 网关**：手机主动隧道、VPS 公网入口、TLS、鉴权、限流和异地调用；
7. **其他改装模块**：信息屏、视频、玩具、网络和路由等逐个形成真实闭环；
8. **Root 实验室与 Root Broker**：仅在机型可恢复、风险已确认且用户本机逐次授权后进入。

首个交付不依赖 VPS。公网阶段当前缺少用户提供或授权购买的 VPS，因此其真实在线验收状态必须保持 `blocked by external VPS prerequisite`，本地 API 通过不能替代公网证明。

## 4. 总体架构

```text
OpenDevice Forge 桌面管理台（后续里程碑）
  ├─ 设备发现与配对
  ├─ 模块目录与生命周期管理
  ├─ 本地 OpenAI 兼容入口
  └─ 公网网关配置
                  │ USB / 同一 Wi-Fi
                  ▼
OpenDevice Node Android 手机端
  ├─ 微内核：设备事实、模块注册、权限、任务、恢复和审计
  ├─ 模型仓库：下载、续传、哈希、许可证、存储和删除
  ├─ AI 模块：llama.cpp、模型加载、推理、流式 API 和本机聊天
  ├─ 模块运行层：内置运行器；后续增加隔离脚本与独立模块 App
  └─ 手机端控制台：节点、模块、连接和状态
                  │ 后续由手机主动建立加密隧道
                  ▼
公网 VPS IP:端口（后续里程碑）
  ├─ TLS 与客户端鉴权
  ├─ 设备路由、限流和连接恢复
  └─ 只转发请求与流式响应，不保存模型、提示词或回复
```

推理始终发生在手机。桌面应用负责管理和提供更方便的本地入口；公网 VPS 只承担轻量安全网关。远程客户端不必安装 OpenDevice Forge，只需使用兼容 OpenAI API 的软件并配置 `base_url` 和 API 密钥。

## 5. OpenDevice Node 微内核

### 5.1 内核职责

手机端内核只负责不可被普通模块替换的能力：

- 读取当前手机的真实系统、ABI、内存、存储、电池和热状态；
- 维护模块来源、清单、安装状态、启停状态、版本、权限和审计记录；
- 提供模块安装、启用、停用、运行、停止、更新、回退、卸载和安全模式；
- 校验模块清单、兼容性、签名、哈希和权限；
- 管理前台服务、任务取消、崩溃隔离和恢复入口；
- 提供版本化能力 Broker，让模块只能调用已声明并获授权的功能；
- 管理本机配对、客户端密钥和网络暴露开关；
- 保证控制台、模块管理和恢复入口不会因普通模块故障而不可达。

模型推理、信息显示、视频、玩具、网络和路由行为都属于模块，不进入内核。

### 5.2 跨端模块契约

桌面端和手机端共享一个平台中立的 `opendevice.module.v1` JSON Schema。该 Schema 是 TypeScript、Kotlin 和未来工具链类型的唯一来源，至少包含：

- 模块 ID、名称、版本、发布者和许可证；
- 内核兼容范围、Android 最低版本、ABI 和硬件约束；
- 来源类型与固定的 Release、tag 或 commit；
- 包哈希、发布者签名和可选的回退版本；
- 风险级别、受众和声明权限；
- 运行类型、入口和贡献点；
- 可渲染的配置字段、默认值和验证约束；
- 健康检查、启动/停止语义、日志和结果结构；
- 是否需要独立 APK、脚本沙箱、前台服务或 Root Broker。

未知字段不能被静默接受。未知权限、未固定来源、签名或哈希不匹配、内核不兼容、无可用运行器的模块不能启用。

Schema 的仓库来源文件放在 `packages/core/schema/opendevice.module.v1.schema.json`，现有 TypeScript `PluginManifest` 通过显式适配器逐步迁移，不能以一次性改名破坏已经通过测试的桌面插件生命周期。Android 工程放在 `apps/android-node`，首个包 ID 使用 `dev.opendevice.node`，最低支持 Android 9（API 28），首个构建和真机验收只承诺 `arm64-v8a`。增加其他 ABI 或更低 Android 版本必须有独立构建和真机证据。

### 5.3 模块贡献点

手机端贡献点与现有桌面插件概念保持一致，并增加手机设备形态需要的槽位：

- `navigation`：控制台中的模块入口；
- `overviewSection`：节点首页的有限信息区域；
- `overviewAction`：节点首页快捷操作；
- `configuration`：由宿主按 Schema 渲染的配置；
- `workflow`：有进度、取消、失败和结果的任务；
- `service`：有启动、停止、健康、端点和日志的本机服务；
- `screen`：可全屏或常亮展示的声明式信息屏；
- `deviceControl`：通过能力 Broker 控制蓝牙、USB 或其他已授权设备；
- `companionApp`：独立安装、独立沙箱的原生模块 App；
- `reportSection`：诊断和导出报告的结构化部分。

模块不能替换微内核、权限提示、恢复入口或安全模式。

## 6. 模块类型与隔离

### 6.1 内置可信运行器

由 OpenDevice Node 一同构建、经过项目测试和签名的第一方运行器。首个 AI 模块使用此类型，以便在没有动态代码加载的前提下完成真实推理闭环。它仍然遵循普通模块的清单、启停、配置、任务、健康和审计契约。

### 6.2 声明式模块

只包含清单、宿主可渲染界面、资源和由允许操作组成的工作流。适合时钟、信息屏、设备状态面板和简单流程。声明式模块不能注入任意 HTML、任意 Intent、任意文件路径或 shell 字符串。

### 6.3 隔离脚本模块

用户已确认需要“沙箱内自由编程”。后续脚本运行器支持 JavaScript/WASM 逻辑，但脚本必须运行在声明了 `android:isolatedProcess="true"` 的独立服务进程中。该进程没有自己的 Android 权限，只能通过 Binder 能力 Broker 请求经过声明和授权的操作。

脚本默认不能访问：

- 宿主文件、照片、联系人、短信、剪贴板和账号；
- 任意网络、局域网扫描或监听端口；
- 摄像头、麦克风、位置、蓝牙和 USB；
- Android Intent、包安装器、ADB、shell 或 Root；
- 其他模块的配置、密钥、提示词和日志。

每个脚本实例具有 CPU 时间、内存、输出大小、请求频率和最长运行时间配额。能力调用由内核记录，停用或卸载模块会立即撤销能力。脚本崩溃只终止该实例，不能终止控制台。

### 6.4 独立模块 App

需要原生推理、视频、摄像头、蓝牙或 USB 等能力的社区模块以独立 APK 提供。Android 系统必须展示安装确认；模块运行在自己的应用 UID 和权限沙箱中，通过显式、受保护的 Bound Service 与 OpenDevice Node 通信。

控制台不能静默安装未知 APK，不能把第三方原生代码动态加载进自身进程。模块 App 的签名、包名、版本和服务接口必须与清单一致，停用后不能继续向控制台贡献入口。

### 6.5 Root 特权模块

Root 模块不获得无限制的常驻 Root shell。后续 Root Broker 只暴露经过审核的能力，例如指定网络规则、启动策略或设备节点操作；每项能力拥有参数约束、超时、审计和可行时的回滚。

任意 Root shell 只能作为本机开发者实验能力，每次在手机屏幕上确认，不能由公网、GitHub 安装流程、自动更新或后台任务静默触发。

## 7. GitHub URL 安装契约

GitHub 安装在后续里程碑实现，但本次必须固化如下行为，避免模块格式重新设计：

1. 用户粘贴 GitHub 仓库、Release、tag 或 commit URL；
2. 仓库首页 URL 只用于读取可选稳定发行版，不能直接跟随默认分支执行；
3. 安装版本必须解析为不可变 Release 资产或完整 commit SHA；
4. 包必须包含 `opendevice.module.json`、许可证、资产哈希和发布者签名；
5. 控制台先展示来源、版本、许可证、权限、兼容性、风险和回退信息；
6. 下载完成后先校验签名与 SHA-256，再放入应用私有或受控存储；
7. 安装后的模块默认停用，用户明确启用后才可运行；
8. 原生 APK 继续交给 Android 系统安装界面确认；
9. 更新重复同一套固定来源、权限差异和完整性检查；
10. 更新失败或健康检查失败时回退上一已验证版本，无法回退则保持停用并进入安全模式提示。

缺少清单、固定版本、签名、哈希、许可证或权限声明的 GitHub 包可以查看诊断原因，但不能安装或运行。未知来源不自动更新。

## 8. 插件发现中心

插件发现中心是一个带多来源提供器的应用商店，而不是把 GitHub 搜索结果原样展示给用户。首批来源契约包括：

- `official`：由 OpenDevice Forge 签名、审核和维护的官方目录；
- `community`：有发布者身份、自动检查和人工举报机制的社区目录；
- `github`：固定到 Release、tag 或完整 commit 的 GitHub 模块；
- `local`：用户主动选择的本地 `.odmodule` 包或独立模块 APK。

用户可以按名称、类别或自然语言用途搜索，例如“把手机变成桌面天气屏”或“控制蓝牙小车”。系统把查询转换为能力需求，再使用当前手机实测的 Android 版本、ABI、内存、存储、屏幕、传感器、蓝牙、USB 和 Root 状态筛选结果。未知设备事实保持未知，不能为了给出推荐而假定硬件存在。

搜索结果排序优先考虑：

1. 当前设备真实兼容性；
2. 来源、签名、固定版本和许可证完整性；
3. 所需权限、风险和可回退性；
4. 发行活跃度、问题响应和依赖健康；
5. 与用户用途的匹配度。

星标、下载量或好评数只能在来源真实提供且可验证时展示，不能生成虚构社会证明。每个结果必须明确标记 `可安装`、`设备不兼容`、`需要 Root`、`来源未验证`、`权限风险较高` 或 `尚无可用运行器`。

插件详情像 App 详情页一样展示图标、截图或预览、用途、发布者、版本、更新记录、许可证、包大小、权限、设备兼容性、来源证据和唯一主要操作。系统可以主动搜索、比较和推荐，但不能静默安装：用户必须在手机上查看最终权限和风险差异后确认，安装完成后模块仍然默认停用。

## 9. 插件创作中心

### 9.1 统一包格式

可视化制作器和开发者 SDK 都输出签名归档 `.odmodule`。包内结构固定为：

- `opendevice.module.json`：身份、版本、兼容、来源、权限、贡献点和运行入口；
- `LICENSE`：插件许可证；
- `README.md`：用途、使用和恢复说明；
- `assets/`：图标、截图、声明式界面资源；
- `runtime/`：可选的沙箱脚本或 WASM 产物；
- `SHA256SUMS`：所有包内资产的哈希；
- `SIGNATURE`：发布者对清单和哈希集合的签名。

独立模块 APK 不嵌入 `.odmodule` 动态执行；`.odmodule` 只携带 APK 来源、包名、签名指纹、版本和服务契约，实际安装仍由 Android Package Installer 确认。

### 9.2 可视化制作器

桌面端提供完整创作工作台，适合组合页面、按钮、列表、图表、数据源、定时器、条件、通知和受控设备动作。手机端提供轻量制作器，适合现场修改信息屏、快捷动作、数据绑定和简单自动化。

制作器只允许选择能力 Broker 已实现的动作。它根据实际使用的组件自动生成最小权限清单，不能通过隐藏字段注入任意 shell、Intent、文件路径或网络地址。预览使用模拟设备事实；发布前必须再用真实设备运行兼容检查。

可视化插件可以导出、导入和本地分享，也可以升级为开发者工程继续编写脚本；从代码工程返回可视化编辑只保证保留可视化子集，不能假装理解任意代码。

### 9.3 开发者 SDK

SDK 提供版本化类型、模块模板、示例、模拟设备、权限检查、沙箱运行器、日志、测试夹具和命令行工具。基本工作流为：

`init → develop → validate → test → pack → sign → local-install`

SDK 至少支持声明式模块、JavaScript/WASM 沙箱模块和独立模块 App 契约。验证器必须复用控制台的同一份 JSON Schema、权限定义和兼容规则，避免开发环境通过而手机拒绝的契约漂移。

本地安装和测试不等于公开发布。上传 GitHub Release、提交社区目录、签署官方目录或发送给其他用户都属于外部写入，必须由创建者明确触发并在发布前重新显示包内容、权限和签名身份。

## 10. 手机端信息架构

OpenDevice Node 使用四个稳定入口，普通用户无需电脑即可完成管理：

### 10.1 节点

- 当前设备真实身份和资源；
- 当前运行模块和主要服务；
- 一个主要操作：启动、停止或处理阻塞；
- 本机聊天测试；
- USB、局域网和后续公网连接状态。

### 10.2 模块

- 已安装、可发现和需要处理的模块；
- 模块来源、版本、权限、兼容性和健康；
- 安装、启用、停用、打开、更新、回退和卸载；
- 首个交付只展示真实可运行的 AI 模块和内核模块，不展示未实现概念模块。

### 10.3 连接

- 默认关闭外部网络访问；
- USB、同一 Wi-Fi 和后续公网网关分别配置；
- 配对码、逐客户端密钥、撤销和密钥轮换；
- 活动客户端、最近连接和失败原因；
- 复制 OpenAI 兼容 `base_url` 的明确入口。

### 10.4 状态

- 模块任务、模型加载、活动请求和错误；
- 首字延迟、tokens/s、峰值内存、温度和电量；
- 可过滤、可导出的结构化日志；
- 安全模式、恢复和最近审计事件。

每屏只有一个主要操作。不存在运行器或真实状态的模块不能显示“启动”“安装成功”或模拟数据。

## 11. 第一个真实模块：AI 模型节点

### 11.1 技术方向

手机应用采用原生 Android Kotlin + Compose。推理层使用 llama.cpp 官方 Android 绑定或等价的固定版本 JNI 集成，作为非导出的前台服务运行；不依赖 Termux，不要求 Root，不通过 shell 启动任意二进制。

首个支持模型为 `Qwen/Qwen3-0.6B-GGUF` 的 `Q8_0` 量化，许可证为 Apache-2.0。实施时必须将模型仓库解析到不可变 revision，记录准确文件名、大小和 SHA-256；运行时不能跟随浮动分支。默认上下文 2048、单请求队列、有限输出长度和流式返回。只有 CDL-AN50 的实测内存、速度和温度通过后，才评估更大模型或更长上下文。

### 11.2 模型仓库

模型仓库负责：

- 展示模型来源、许可证、量化、文件大小、所需空闲空间和兼容状态；
- 在手机端直接下载，不依赖电脑推送；
- 暂停、续传、失败重试和用户取消；
- 下载后校验不可变 revision、文件长度和 SHA-256；
- 校验失败时隔离临时文件并拒绝加载；
- 在应用私有存储或经过 Storage Access Framework 授权的目录管理模型；
- 删除前停止使用该模型的服务并解释影响；
- 不把“已下载”当作“已加载”或“服务已就绪”。

### 11.3 推理与本机体验

统一状态机：

`未安装模型 → 下载中 → 校验中 → 可加载 → 加载中 → 服务中 → 停止中 → 已停止`

错误分支包括：存储不足、网络失败、哈希不匹配、格式不支持、内存不足、原生运行器崩溃、温度过高、请求取消和系统回收。错误保留可恢复数据，不能伪装为全部成功。

本机聊天和远程 API 使用同一个推理服务、同一个模型配置和同一队列。本机聊天只用于验证与使用，不维护另一套推理实现。

前台服务必须展示持续通知，包含当前模型、服务状态和停止操作。启动必须由可见界面的用户操作触发；系统禁止后台启动时显示明确原因，不以 Root 绕过 Android 限制。

### 11.4 热、内存和电量保护

- 加载前检查总内存、可用内存和空闲存储；
- 运行时记录进程内存、Android 热状态、电池温度和电量；
- 首个交付只允许一个并发生成请求，其余进入有限队列或返回繁忙；
- 达到严重热状态时拒绝新请求并取消或安全结束当前生成；
- 内存压力时缩减可安全调整的缓存，否则卸载模型并返回明确错误；
- 不宣称后台永久存活；熄屏、切后台和 OEM 电源管理行为必须真机验证并在 UI 中解释。

## 12. 本地 OpenAI 兼容 API

首个交付实现：

- `GET /health`：服务和模型就绪状态；
- `GET /v1/models`：当前已加载和可服务的模型；
- `POST /v1/chat/completions`：非流式与 SSE 流式聊天；
- 标准 Bearer 鉴权、请求 ID、超时、取消和结构化错误。

模型 API 不包含下载、删除、模块安装、改密钥或 Root 等管理操作。手机界面与未来桌面插件通过非导出的本机接口或受保护 Binder 执行管理，不通过公共模型 API。

首个默认端点为 `http://127.0.0.1:8080/v1`。端口可在服务停止时修改，范围限制为 1024–65535，并在启动前检测冲突；实际监听地址和端口始终显示在手机界面。环回地址的 `/health` 可以无鉴权返回最小就绪状态，同一 Wi-Fi 模式下包括健康检查在内的所有端点都必须验证 Bearer 密钥。

网络模式：

- **本机**：手机 UI 直接绑定内部服务；
- **USB**：服务监听手机环回地址，电脑通过受控 ADB 端口转发验证；
- **同一 Wi-Fi**：用户在手机上明确开启局域网监听，Bearer 密钥必需；
- **公网**：首个交付不可用，后续只通过手机主动建立的加密网关连接。

提示词、回复和 API 密钥不能写入普通日志。默认日志只记录请求 ID、时间、模型、token 数、耗时、结果码和资源指标。

## 13. 公网 IP 网关契约

公网阶段需要用户提供或授权购买具有公网 IP 的 VPS。手机通常位于家庭 NAT 或蜂窝 CGNAT 后，设计不假设手机自身拥有可入站连接的公网 IPv4。

后续网关必须满足：

- 手机主动建立带设备身份的 mTLS 或等强度长连接；
- 外地客户端访问 `https://公网 IP:端口/v1`；
- 每个客户端拥有独立、可撤销的 API 密钥；
- 公网入口具有 TLS、请求大小限制、并发限制、速率限制和超时；
- 网关不记录提示词、回复、模型文件或手机密钥；
- 隧道断开后返回节点离线，不把请求转发到其他设备；
- 证书、隧道或鉴权失败时关闭入口，不能回退为公网明文 HTTP；
- 支持自动续期的公网 IP TLS 证书。Let’s Encrypt 公网 IP 证书有效期很短，续期与失败关闭必须自动化；
- 裸 API 密钥不能替代 TLS，因为明文传输会泄露密钥和提示词。

公网网关的服务购买、凭据写入、端口开放和正式部署都需要在精确控制点获得用户新授权。

## 14. 权限、隐私与安全模式

### 14.1 默认权限

内核和 AI 模块只请求首个闭环必需的网络、前台服务、通知和受控存储能力。摄像头、麦克风、位置、蓝牙、USB 和包安装等权限在对应模块实际使用时再就地请求。

模块权限必须同时出现在清单、安装确认、系统权限和审计记录中。清单声明不能自动授予 Android 系统权限。

### 14.2 密钥

- 设备身份私钥和本机配对密钥由 Android Keystore 生成或保护；
- 每个客户端使用独立令牌，可单独撤销；
- 密钥只显示一次或通过配对安全传递，日志和报告中只显示指纹；
- 重置节点会撤销所有客户端和公网隧道身份。

### 14.3 安全模式

以下情况进入安全模式：模块连续启动崩溃、签名或哈希变化、权限清单异常、版本回退失败、脚本配额严重违规或 Root Broker 不一致。

安全模式停用第三方模块和脚本，不删除模型或配置；内核、模块列表、审计、导出和恢复入口始终可达。AI 第一方模块可被单独停用，不能绕过内核恢复规则。

## 15. 错误处理与恢复

| 场景 | 用户可见状态 | 系统行为 | 恢复路径 |
| --- | --- | --- | --- |
| 手机资源尚未读取 | `设备信息待检测` | 不推断型号规格或兼容性 | 重新检测或连接 ADB |
| 模型存储不足 | `空间不足` | 下载前阻止任务 | 删除模型或选择受控目录 |
| 下载中断 | `已暂停/网络失败` | 保留可续传临时文件 | 恢复网络后续传 |
| 哈希或签名失败 | `文件校验失败` | 隔离文件，禁止加载 | 删除并从固定来源重下 |
| 模型加载 OOM | `内存不足，模型未加载` | 释放部分状态并卸载模型 | 降低上下文或选择更小模型 |
| 温度过高 | `温控暂停` | 拒绝新请求并安全停止生成 | 降温后用户恢复 |
| 前台服务被系统停止 | `服务已被系统停止` | 不伪装在线 | 用户从可见界面重启并查看电源建议 |
| 客户端密钥错误 | `未授权` | 不泄露模型或节点详情 | 重新配对或轮换密钥 |
| 网络切换或断开 | `连接已中断` | 取消或结束流式请求 | 客户端重试，手机保持本地可用 |
| 模块崩溃 | `模块异常` | 停用该模块，保留内核 | 重试、回退或安全模式卸载 |
| 公网 VPS 不存在 | `尚未配置公网网关` | 不展示可用公网地址 | 提供 VPS 后进入独立部署里程碑 |
| Root 不可用 | `未启用 Root 能力` | 普通模块继续工作 | 只在 Root 实验室评估 |

## 19. 已批准的产品决策

- 首台真实验证设备为 HUAWEI CDL-AN50；
- 最终需要公网 IP 远程调用，但当前没有 VPS；
- 采用专用手机端 App，不采用 Termux 作为正式产品运行时；
- 手机端必须能脱离电脑独立下载模型和管理服务；
- 手机负责推理和独立管理，桌面是可选的远程管理台，VPS 只负责安全转发；
- 产品是通用废旧手机模块控制台，AI 只是第一个模块；
- 后续支持经过校验的 GitHub URL 模块安装；
- 控制台可以主动搜索、筛选和推荐插件，但安装必须由用户在手机上确认；
- 插件像 App 一样具有详情、版本、权限、兼容性、更新和独立工作台；
- 普通用户使用可视化制作器，开发者使用 SDK，两者输出同一种 `.odmodule`；
- 脚本允许在隔离沙箱内自由编程，不允许默认继承宿主或 Root 权限；
- 公网必须使用加密传输，API 密钥不能替代 TLS；
- Root 是本机逐次确认、可恢复、受能力约束的后续实验层。
