# OpenDevice Forge 插件工作台设计

> 状态：方向已确认，等待书面规格复核
> 日期：2026-08-16

## 目标

把 OpenDevice Forge 收敛成一个插件优先的桌面设备工具：内核只负责发现和选择设备、管理插件及承载插件 UI；设备连接后的检测、调试、报告、模型、路由和本机服务都由插件提供。

本阶段必须交付一个真实闭环，而不是插件介绍页：用户能够安装或启用插件，打开插件工作台，修改有效配置，执行真实任务并查看真实结果。

本阶段不实现公网远程控制、Root、解锁或刷机，也不执行来自任意路径的脚本或命令。

## 产品边界

### 内核保留

- Android 设备发现、选择、连接状态和基础身份读取；
- 插件目录、安装、启用、停用、卸载和恢复；
- 插件配置存储、权限边界、运行状态和结果承载；
- 受控的插件运行器注册表；
- 插件市场与插件工作台的稳定入口。

### 插件负责

- 设备体检、报告导出和 AI 运行条件判断；
- 后续的模型运行器、路由配置、视觉工具和本机 API；
- 自己的配置定义、运行入口、进度、结果和错误说明；
- 需要时提供本机服务状态、端点和日志。

只有存在真实运行器的插件才能显示“运行”或“安装”。没有实现的概念不作为已安装插件出现，也不能用说明页冒充工作台。

## 整体信息架构

### 设备入口

左侧设备栏保留手机图、实测型号、连接状态、设备选择和重新检测。导航只保留：

1. `设备`：查看当前设备身份、关键事实和已经可用的插件入口；
2. `插件市场`：发现、安装、启停和打开插件。

删除模拟窗口按钮、返回/前进、无实现的刷新/帮助、`核心（不可移除）`、锁图标、左下角只读宣言和底部安全横条。安全约束保留在运行器和权限层，不反复占用界面。

### 插件市场

插件市场采用“目录列表 + 选中插件详情”的桌面结构：

- 顶部只保留页面标题、搜索和必要分类；
- 分类第一阶段为 `已安装` 与 `发现`，没有真实数据的更新、来源页暂不展示；
- 列表显示名称、用途、来源和安装状态；
- 详情显示插件能做什么、需要的权限、设备兼容性及唯一主操作；
- 未安装插件的主操作是`安装`；已安装且停用的是`启用`；已启用且有运行器的是`打开工作台`；
- 回退、卸载和来源详情放入次级区域，不与主操作争夺视觉层级。

### 插件工作台

安装后的插件在同一个主工作区内打开，不弹出各自风格不同的小窗口。统一包含：

- `运行`：插件的主要任务、开始/停止和进度；
- `配置`：只渲染插件真实声明且运行器会消费的设置；
- `结果`：本次运行结果、失败原因和再次运行入口。

没有配置项的插件不显示空的`配置`页。没有执行结果时显示明确空状态，不生成示例结果。

## 第一个真实插件：设备体检

### 配置

设备体检提供四个可选检测组，默认全部开启：

- 设备身份：厂商、型号、产品代号、Android 版本和架构；
- 性能基础：运行内存和可用存储；
- 电源状态：当前电量；
- 系统状态：ADB 连接与现有只读 Root 信号。

配置存储在电脑本地，按插件保存；USB 序列号不显示、不导出，也不作为配置内容保存。

### 运行

用户点击`开始检测`后，工作台调用当前设备会话的受控只读检测适配器。运行中锁定重复提交并显示当前阶段；设备断开、未授权或读取失败时停止并提供重新检测入口。

### 结果

结果按已选择的检测组展示，明确区分“读取成功”“设备未提供”和“读取失败”。结果不得用机型资料库补齐未知字段。用户可在结果页再次检测；报告导出仍作为独立插件，不混入首个闭环。

## 插件运行契约

第一阶段只运行随应用发布并在代码中注册的受控插件，不加载任意 JavaScript、动态库或 shell 字符串。

每个可运行插件由四部分组成：

1. `manifest`：身份、版本、来源、权限、兼容性和贡献入口；
2. `configuration schema`：由宿主渲染的受控字段定义；
3. `runtime adapter`：接收当前设备、已验证配置和取消信号，返回结构化进度与结果；
4. `result schema`：由宿主渲染的分组结果、状态和可执行后续动作。

运行器状态统一为 `idle / running / success / error / cancelled`。插件停用或卸载时不能继续启动任务；正在运行的任务必须先取消或结束。

配置字段第一阶段只支持复选组、开关、数字、文本和选择项。宿主负责默认值、验证、持久化和无障碍标签；插件不能注入任意 HTML。

## 后续单文件程序与本机服务接口

单文件模型运行器、路由器或其他工具未来通过 `service` 运行器接入，而不是另建一套产品结构。服务插件在工作台中沿用`运行 / 配置 / 结果`，并可增加以下结构化状态：

- 服务的`stopped / starting / running / error`状态；
- 由宿主分配或验证的本机端口；
- 本机 API 地址和健康检查；
- 标准输出、标准错误和结构化日志；
- 启动、停止与重启操作；
- 插件声明的路由或配置文件编辑器。

安全边界：可执行文件必须来自已固定版本的插件包，由宿主以固定参数数组启动，不经过 shell；默认只监听本机地址；公网暴露、远程凭据和自动下载不属于本阶段。

本阶段只定义并测试能够区分 `workflow` 与 `service` 的类型接口，不启动真实远程网关或第三方可执行文件。

## 状态与错误路径

- 无设备：市场仍可浏览；需要设备的插件工作台显示连接设备入口；
- 未授权或离线：保留插件配置，禁止运行并解释原因；
- 运行中断：结果页保留已完成组，失败组显示错误，不伪装全部成功；
- 无兼容运行器：插件不能安装或打开；
- 配置无效：在字段旁显示错误，不能启动；
- 插件停用：保留配置和最近结果，但停止贡献入口；
- 安全模式：只影响第三方插件，市场和恢复入口仍可到达，但不常驻顶部工具栏。

## 视觉与交互规则

- 延续 iMazing 式设备身份锚点和 VS Code 式插件目录/详情关系，但不复制品牌资产或编辑器皮肤；
- 工作区使用开放的白色桌面表面，主要层级靠栏宽、分隔线和留白，不靠等宽卡片堆叠；
- 每屏只有一个蓝色主操作；启停开关、次级文本按钮和危险操作分别处理；
- 图标继续统一使用 Lucide，尺寸和描边保持一致；
- 桌面基线为 1280×800；1024px 宽度下插件目录缩窄，工作台仍保持可操作且不横向溢出；
- 动效只用于运行进度、页签切换和状态变化，并支持 `prefers-reduced-motion`；
- 安全限制在需要授权或危险动作时就地出现，不以常驻横条反复解释。

## 实现切片

当前 Goal 按以下顺序实现：

1. 精简应用外壳和插件市场，移除无效装饰控件；
2. 增加插件运行器、配置、结果以及 `workflow/service` 的类型边界；
3. 将设备体检接入工作台并完成真实配置、运行和结果闭环；
4. 让市场只对真实可用插件提供安装和打开入口；
5. 完成自动化、双宽度和 nova 7 原生真机验证。

报告导出、AI 条件判断和后续模型/路由服务将在本 Goal 验收后沿相同工作台契约逐个迁移，不作为首个真实插件闭环的完成前置条件。

## 验收证据

完成必须同时满足：

- 原生 App 中不存在已指定删除的模拟按钮和常驻只读说明；
- 用户能从插件市场安装/启用设备体检并打开工作台；
- 四组配置至少关闭一组后，运行结果确实不包含该组，刷新应用后配置仍存在；
- 连接中的 HUAWEI CDL-AN50 能完成一次真实只读检测，并显示身份、内存、存储、电量和系统状态；
- 未连接、未授权、运行中、成功和失败状态均有自动化测试；
- 插件生命周期、配置验证、运行状态和 `workflow/service` 类型边界有核心单元测试；
- 桌面组件测试覆盖市场到工作台的主流程；
- Playwright 覆盖 1280×800 与 1024px 的主要路径、键盘焦点和无横向溢出；
- 新构建的 macOS App 通过签名校验，并在真机原生窗口完成截图复核；
- 整个过程没有 Root、刷机、解锁、手机端安装或公网远程访问。

## 不在本阶段

- 任意 GitHub 仓库一键执行；
- 第三方原生插件动态加载；
- 模型下载、微调或推理服务；
- 远程网关、公网端口映射或账号系统；
- Root、Bootloader 解锁、刷写和恢复；
- iOS 设备提供器。
